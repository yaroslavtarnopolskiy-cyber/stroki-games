# «Песни Земли»: размещение в S3 Строк

Версия пакета: 17 ноября 2026, RC1. Пакет подготовлен, но публикация в S3 этим обновлением репозитория не выполнялась.

## Сначала собрать пакеты

Из корня репозитория:

```bash
python3 scripts/package-s3.py --output output/releases/current
```

Пакеты появятся в `output/releases/current/`. Архивы содержат все игры и графику; бинарные ресурсы не меняются. ZIP по 171 MiB превышают ограничение одного файла обычного GitHub-репозитория, поэтому здесь сохранены полные исходные материалы, воспроизводимый сборщик и эта инструкция.

## Что передать

- Для RC: `pesni-zemli-rc.zip` или уже распакованную папку `rc/pesni-zemli`.
- Для будущего PROD: `pesni-zemli-prod.zip` / `prod/pesni-zemli`. Этот вариант подготовлен из той же версии; после исправлений по RC его нужно пересобрать.
- По 629 файлов в каждом пакете, примерно 178 MiB после распаковки и 171 MiB ZIP.
- Веб-папка содержит только готовый лендинг, игры и ресурсы. Внутри нет ключей доступа, Git, ревью или тестовых скриптов.

## Загрузка на RC

1. Открой существующее соединение с S3, бакет `landings.rc.stage.books.mts.ru` (как на твоём скриншоте).
2. Если передаёшь ZIP — сначала распакуй его на компьютере. S3 не распаковывает ZIP автоматически.
3. Перетащи папку `pesni-zemli` из `rc/` в корень бакета, рядом с `gifts`, `landing` и другими лендингами. Если папка с таким именем уже существует, сначала проверь, что это именно наш проект; не заменяй чужой лендинг.
4. Дождись окончания загрузки всех файлов. Внутри должно получиться:

```text
landings.rc.stage.books.mts.ru/
└── pesni-zemli/
    ├── index.html
    ├── assets/
    ├── games/
    ├── story-matcher/
    ├── map-study/
    ├── album-promo/
    └── остальные файлы и папки пакета
```

Не должно появиться дополнительного уровня `dist`, `rc` или `pesni-zemli/pesni-zemli`.

5. После загрузки открой:

**https://landings.rc.stage.books.mts.ru/pesni-zemli/**

Если CDN не подставляет индекс для папки:

**https://landings.rc.stage.books.mts.ru/pesni-zemli/index.html**

Эти адреса предназначены для будущей загрузки, а не подтверждают состоявшуюся публикацию.

## Типы файлов и кэш

Если S3-клиент сам определяет типы по расширению, оставь автоопределение. Для удобства ES-модули в пакете имеют расширение `.js`; ссылки на них согласованно обновлены. Для диагностики есть `rc-upload-manifest.csv`: ключ каждого объекта, размер, SHA-256, Content-Type и рекомендуемый Cache-Control.

Критичные типы:

| Расширение | Content-Type |
|---|---|
| `.html` | `text/html; charset=utf-8` |
| `.js` | `application/javascript` или `text/javascript` |
| `.css` | `text/css; charset=utf-8` |
| `.svg` | `image/svg+xml` |
| `.webp` | `image/webp` |
| `.mp4` | `video/mp4` |

HTML рекомендуется отдавать с `Cache-Control: no-cache, max-age=0`. Для JS/CSS в манифесте предложен короткий кэш, для изображений — сутки. Итоговые правила CDN могут переопределять эти заголовки. При последующих заменах файлов, если CDN показывает старую версию, потребуется сброс кэша со стороны ответственной команды.

`.htaccess` и `web.config` для этого лендинга не нужны: все страницы статические; игры находятся в собственных HTML, навигация использует якоря и параметры URL. Настройки самого бакета/CDN пакет не меняет.

## Проверка после загрузки

- Страница открывается как сайт, а не скачивается файлом.
- Меняются темы, раскрываются земли и перелистываются карточки.
- Все три игры запускаются по кнопке; два последовательных крестика завершают и закрывают игру.
- У раннера работают встреча с колдуньей и финал у палатки.
- Подбор выдаёт рассказ, «К истории» ведёт по диплинку, «Поделиться» создаёт картинку.
- Скопированная ссылка остаётся на RC и открывает нужный рассказ.
- На iPhone/Android: поворот для горизонтальных игр, звук, свайпы и прокрутка.
- В Network нет 404 и ошибок типа JS-модулей; PNG/SVG/шрифты загружаются.
- Превью ссылки в Telegram проверяется после реального размещения: локальный тест не подтверждает работу Telegram crawler/CDN.

В RC добавлен `noindex,nofollow` (это просьба поисковикам, не ограничение доступа). Боевой счётчик Метрики 89251519 сохранён; RC-визиты отличаются адресом страницы.

## Передача на PROD

По инструкции «Лендинги S3» тестирование и ручная загрузка на RC выполняются исполнителем. Перенос проверенного лендинга на PROD выполняет DevOps, затем актуальная версия сохраняется в GitLab.

- Будущий адрес: **https://landings.stroki.mts.ru/pesni-zemli/**.
- Передай DevOps согласованный PROD-пакет, `prod-upload-manifest.csv` и `release-manifest.json`.
- Не переноси RC `index.html` без замены: в нём RC-адреса Open Graph и запрет индексации. В подготовленном PROD-пакете они уже корректны.
- Игры, изображения и остальные файлы RC/PROD идентичны. Изображения не перекодировались и не сжимались дополнительно.
- После любых дальнейших изменений лендинга собери оба пакета заново и повтори проверку RC.
- Репозиторий актуальных PROD-лендингов: https://gitlab.services.mts.ru/digital-products/stroki/frontend/landings. Запись в корпоративный GitLab выполняет команда с соответствующими правами.
